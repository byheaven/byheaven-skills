# Review presentation

Before the task owner requests judgment on any concrete review object, present that exact object in a form the user can open in their current client, including during remote control. When interaction affects the decision, the user must be able to perform it in the presented object. A host-only file path, localhost URL, or desktop panel does not establish remote access; source code alone does not present a rendered UI. Where the object includes a surface that already exists, its rendering derives from that surface's own styles and structure; an approximation reconstructed from description is a different object, and approval of it does not carry to the real surface. The presentation identifies its exact durable or version-bound source, and approval binds to that source object and version. Establish that the carrier is accessible in the current client, reusing still-current capability evidence. If it is inaccessible, choose an accessible equivalent within existing authority; if none is available, the review gate remains open. Changing carriers does not expand publishing, audience, data-sharing, or product-release authority. Runtime bindings map available mechanisms to these requirements.

The review page carries only what can change the user's next choice: the object rendered at the viewport of the device they review on, each open decision, and any consequence that would change that decision. An open decision is one the user owns that no source under [Frontier admission](direction.md#grill) settles; a settled decision shows only inside the object, and a proposal without current value is dropped rather than asked. Candidates differ in rendered form, switched in the same place, with text only for a consequence rendering cannot show. Rationale, evidence, process, settled decisions, and rejected alternatives stay off the page, except one line on why the recommended option is recommended; the task record and repository artifacts are their record. This ceiling bounds the page presented for judgment; what a source-local standard records inside its own repository artifact is unaffected.

A periodic review's concise conversational outcome commitment may itself be the review object, with rendered chat as its carrier.
