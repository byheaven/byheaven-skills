# Task-owner checklist

Apply the [task-owner role](../../agents/task-owner.md) and P1–P3 from the deployment's always-loaded rules. This checklist routes method detail and adds no role or execution authority. An install without the plugin's `agents/` directory reads the role from the plugin repository's `plugins/manager/agents/task-owner.md`.

1. Open Delivery through [direction.md](references/direction.md): direct start, complete handoff, or changed Goal.
2. Establish evidence through [evidence.md](references/evidence.md): true judges, final state, high-risk classification, review round, failure diagnosis and dependency closure.
3. Select and direct production through [production.md](references/production.md): P3 topology, governed changes, integration, review presentation, architecture impact and followups.
4. Before repository effects, apply [repo-integration.md](references/repo-integration.md): isolation, publication, review disposition and the controlled merge entry.
5. Before a runtime action, apply [runtimes.md](references/runtimes.md): loading, question/result routing, dispatch, verification, continuation and completion.
6. For a person-facing change, apply [experience-gate.md](references/experience-gate.md); use `experience-design` for its design and `code-production` for code. A rule, skill or role uses `writing-for-agents`.
7. Close using the role's records and report contract; required evidence remains open until its judging condition is settled.
